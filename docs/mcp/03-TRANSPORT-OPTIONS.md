# MCP 메시지 전송 계층 옵션 비교

**작성일**: 2025년 11월 7일  
**목표**: TCP vs Redis vs Pulsar 비교 및 선택 가이드

---

## 📋 세 가지 전송 옵션 비교

### 1️⃣ TCP (기본 프로토콜 - 현재 설계)

#### 장점
- ✅ **심플**: 의존성 없음, 직접 구현
- ✅ **저지연**: 직접 연결로 가장 빠름
- ✅ **완전 제어**: 프로토콜 세부사항 완전 관리
- ✅ **교육용**: MCP 개념 이해하기 좋음

#### 단점
- ❌ **상태 관리**: 서버 재시작 시 연결 모두 끊김
- ❌ **확장성**: 수평적 확장 어려움
- ❌ **메시지 보존**: 메시지 히스토리 저장 안 됨
- ❌ **분산 처리**: 다중 서버 인스턴스 불가능

---

### 2️⃣ Redis (경량, 빠른 메시징) 🌟 권장

#### 장점
- ✅ **빠른 메시징**: 매우 낮은 지연시간 (< 1ms)
- ✅ **메시지 보존**: Redis Streams로 메시지 히스토리 관리
- ✅ **Pub/Sub**: 자체 Pub/Sub 메커니즘 지원
- ✅ **캐싱**: 상태/메타데이터 캐싱 가능
- ✅ **간단한 배포**: Docker로 쉽게 배포
- ✅ **개발 속도**: 빠르게 프로토타입 가능

#### 단점
- ⚠️ **메모리 한계**: 메모리 기반 (큰 메시지 히스토리 비효율)
- ⚠️ **지속성**: 메모리 손실 시 데이터 손실 (RDB/AOF로 완화)

---

### 3️⃣ Apache Pulsar (강력한 메시징 플랫폼)

#### 장점
- ✅ **무제한 메시지 보존**: 디스크 기반 저장
- ✅ **확장성**: 수평적 확장 완벽 지원
- ✅ **고가용성**: Multi-Broker 레플리케이션
- ✅ **엔터프라이즈 준비**: 높은 SLA 보장

#### 단점
- ⚠️ **복잡도**: 설정/관리가 복잡
- ⚠️ **리소스**: 더 많은 리소스 필요

---

## 📊 성능 비교

| 항목 | TCP | Redis | Pulsar |
|------|-----|-------|--------|
| **지연시간** | 1-5ms | < 1ms | 5-10ms |
| **처리량** | 1K msg/s | 100K msg/s | 1M+ msg/s |
| **메시지 보존** | ❌ | ⚠️ | ✅ |
| **수평 확장** | ❌ | ⚠️ | ✅ |
| **배포 복잡도** | 낮음 | 낮음 | 높음 |

---

## 💡 권장 선택

### Phase 1: Redis (지금 바로 시작)
```bash
docker run -d -p 6379:6379 redis:7-alpine
pip install redis aioredis
```

**이유**:
- ✅ 빠른 개발
- ✅ 메시지 보존
- ✅ 쉬운 배포
- ✅ 나중에 Pulsar로 마이그레이션 가능

### Phase 2: Pulsar (대규모 필요시)
```bash
docker-compose up -d  # Pulsar + Manager
```

### 마이그레이션 경로
```
Redis → Pulsar:
- 메시지 프로토콜 동일 유지
- Broker만 교체
- 클라이언트 코드 최소 변경
```

---

**결론**:
- ✅ **시작**: Redis
- ✅ **나중**: Pulsar
- ✅ **프로덕션**: 둘 다 또는 하이브리드
